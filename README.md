# ЕГЭ Обществознание — интерактивный тренажёр

Веб-приложение для подготовки школьника к ЕГЭ по обществознанию. Полностью на русском языке, мятная светлая тема + переключатель тёмной, адаптивная вёрстка (мобильный drawer-сайдбар + десктоп), заставка с розовым слоником при загрузке.

🔗 **Демо (GitHub Pages):** https://realfactchecknews-eng.github.io/ege-obshestvoznanie/
📦 **Репозиторий:** https://github.com/realfactchecknews-eng/ege-obshestvoznanie

> **Этот README — точка входа для разработчика или ИИ-ассистента, продолжающего проект.** Ниже описаны архитектура, схемы данных, карта файлов, соглашения и пошаговые рецепты типовых доработок. Читается без знания истории проекта.

## 1. Что это и как устроено в двух словах

Это **статический клиентский SPA** (React + TypeScript + Vite + Tailwind). Вся «база» заданий, теории, терминов и сборника вариантов — это JSON-файлы, которые **бандлятся в сборку** на этапе компиляции. Прогресс ученика (ответы, серии, изученные темы, состояние карточек, результаты вариантов) хранится в **`localStorage`**; при настроенном Firebase — дополнительно синхронизируется в облако.

Папка `/server` — **опциональный** Express + SQLite REST API, не используется развёрнутой на GitHub Pages версией (Pages раздаёт только статику). Источник правды для данных — JSON в `client/src/data/`, `server/data/` — их копии.

```
Пользователь → GitHub Pages (статика из client/dist)
                 ├─ React-приложение (SplashScreen → Dashboard/Practice/...)
                 ├─ tasks.json / theory.json / terms.json / book_variants.json (вшиты в бандл)
                 ├─ localStorage (прогресс, ключи ege2_*)
                 ├─ Firebase (опционально: авторизация + облачная синхронизация прогресса в Firestore)
                 └─ Cloudflare Worker (опционально: ИИ-проверка письменных через OpenRouter)

[опционально, локально] server/ → Express → SQLite (server/db/ege.db)
```

## 2. Технологии

| Слой | Технологии |
|------|-----------|
| Клиент | React 19, TypeScript, Vite 8, Tailwind CSS |
| Состояние/навигация | Локальный React-стейт (без react-router). Переключение экранов — `useState<View>` в `App.tsx`, сайдбар со скользящим индикатором активного пункта |
| Хранение прогресса | `localStorage` (обёртки в `client/src/lib/storage.ts`), опционально Firebase Firestore |
| Авторизация | Firebase Auth (email + пароль), опционально |
| ИИ-проверка письменных | Cloudflare Worker → OpenRouter (см. §11.1) |
| Сервер (опционально) | Node.js (ESM), Express 4, better-sqlite3 |
| Деплой | GitHub Actions → GitHub Pages (`.github/workflows/deploy.yml`) |

Важный нюанс сборки: в `client/vite.config.ts` задан **`base: '/ege-obshestvoznanie/'`** — Pages обслуживает сайт по пути `/<repo>/`. Если репозиторий переименуют, `base` надо поменять, иначе ассеты не загрузятся.

## 4. Схемы данных (важно для добавления контента)

### 4.1. Задание — `client/src/data/tasks.json`

Массив объектов. Поля зависят от `type`. Поддерживаются 5 типов:

| `type` | Что это | Обязательные доп. поля | Формат `correct_answer` |
|--------|---------|------------------------|--------------------------|
| `single` | один правильный вариант | `options: string[]` | **текст** правильного варианта (для текстовых ответов добавь `"options_letters": false`) |
| `multiple` | несколько правильных | `options: string[]` | строка цифр-индексов, напр. `"134"` (порядок неважен, сверяется как множество) |
| `matching` | соответствие колонок | `match_left: string[]`, `match_right: string[]` | строка выбора для каждого левого пункта по порядку, напр. `"2132"` |
| `fill` | вписать слово | — (`options: []`) | слово/словосочетание; сверка нечувствительна к регистру, пробелам и `е/ё` |
| `written` | часть 2 (17–25), ручная/ИИ-проверка | `criteria?: string[]` | эталонный ответ (многострочный текст) или заглушка с указанием проверять через ИИ |

Необязательное поле `image?: string` (путь относительно `public/`, напр. `"graphs/v1_graph21.png"`) — рендерится картинкой под условием задания (используется для графиков спроса/предложения в №21).

Полный пример (multiple):
```json
{
  "id": 61,
  "year": 2024,
  "task_number": 6,
  "type": "multiple",
  "topic": "Экономика",
  "subtopic": "Рыночная экономика",
  "question": "Выберите верные суждения о рыночной экономике.",
  "options": ["вариант 1", "вариант 2", "вариант 3", "вариант 4", "вариант 5"],
  "correct_answer": "134",
  "explanation": "Пояснение со ссылкой на статью закона, напр. «Согласно ст. 8 Конституции РФ…».",
  "source": "ФИПИ 2024"
}
```

Пример matching:
```json
{
  "id": 62, "year": 2023, "task_number": 8, "type": "matching",
  "topic": "Экономика", "subtopic": "Налоги",
  "question": "Установите соответствие между примерами и видами налогов.",
  "match_left": ["НДФЛ", "НДС", "Акциз", "Налог на имущество"],
  "match_right": ["Прямой налог", "Косвенный налог"],
  "correct_answer": "1221",
  "explanation": "…", "source": "ФИПИ"
}
```

Пример written с картинкой (часть 2, задание с графиком):
```json
{
  "id": 500, "year": 2026, "task_number": 21, "type": "written",
  "topic": "Экономика", "subtopic": "Экономическая задача (график спроса/предложения)",
  "question": "Изучите график и ответьте на вопросы...",
  "image": "graphs/v1_graph21.png",
  "options": [],
  "correct_answer": "Эталонный ответ из критериев книги или заглушка с указанием проверять через ИИ",
  "criteria": [],
  "explanation": "Сверь свой ответ с эталоном или проверь с ИИ.",
  "source": "Котова, Лискова — 30 вариантов ЕГЭ 2026, вариант 1"
}
```

Соглашения по `correct_answer`:
- `multiple` — индексы вариантов **с единицы**, в строку без разделителей (`"134"` = варианты 1, 3, 4).
- `matching` — для каждого пункта `match_left` по порядку указывается номер выбранного `match_right` (с единицы). Длина строки = числу левых пунктов.
- Логика сверки — в `client/src/lib/data.ts → checkAnswer()`. Если добавляешь новый тип задания, правь её там же.

### 4.2. Теория — `client/src/data/theory.json`

```json
[
  {
    "section": "Экономика",
    "code": "3",
    "topics": [
      {
        "id": "ec-1",
        "title": "Экономика и экономические системы",
        "text": "Многострочный текст. Переносы строк \\n отображаются как абзацы.",
        "key_terms": ["Экономика", "Факторы производства", "Рента"]
      }
    ]
  }
]
```
- `id` темы используется как ключ в localStorage для отметки «изучено» — **делай его уникальным и не меняй задним числом**.
- `key_terms` рендерятся кликабельными чипами; попап подтягивает определение из `terms.json` по совпадению названия.

### 4.3. Термины — `client/src/data/terms.json`

```json
[
  { "term": "Инфляция", "definition": "Устойчивое повышение общего уровня цен на товары и услуги, сопровождающееся снижением покупательной способности денег.", "topic": "Экономика" }
]
```
Определения пишутся в строгом экзаменационном формате задания 18 ФИПИ: родовое понятие + минимум два существенных признака, без примеров/метафор/оценочных слов — чтобы такое определение реально засчитали на экзамене. Термины используются в попапах теории и в режиме карточек (Leitner).

### 4.4. Сборник вариантов — `client/src/data/book_variants.json`

Массив из 30 объектов (по одному на вариант):
```ts
{
  variant: number,
  tasks: { num, answer, kind: 'ordered'|'unordered', image: boolean, text, graphImage? }[],  // часть 1, №1-16
  part2: { num, topic, text, source_text?, report_topic?, graph? }[],                          // часть 2, №17-25
  criteria_raw: string,  // официальные критерии оценивания части 2 целиком как в книге
}
```
Используется вкладкой «Сборник 30» (`pages/BookVariants.tsx`, логика — `lib/book.ts`) для прохождения целых вариантов книги с официальными критериями. Задания части 1 и 2 из этого файла **также разложены** по номерам в `tasks.json` (см. v2.5/v2.6 в changelog) — так что один и тот же контент доступен и по вариантам целиком, и колодами по номеру.

### 4.5. Разделы (`TOPICS`)

Канонический список из 6 разделов кодификатора задан **строкой** в `client/src/lib/data.ts → TOPICS`. Значение `topic` в заданиях/терминах **должно точно совпадать** с одной из этих строк, иначе задание не попадёт в фильтры и аналитику:
```
Человек и общество · Духовная культура · Экономика · Социальные отношения · Политика · Право
```

## 5. Как хранится прогресс (localStorage)

Все ключи и обёртки — в `client/src/lib/storage.ts`. Никогда не пишите в localStorage напрямую из компонентов, только через эти функции.

| Ключ | Назначение |
|------|-----------|
| `ege2_answers` | массив `AnswerResult` — каждый ответ (taskId, taskNumber, topic, correct, date, ts) |
| `ege2_learned` | `{ [themeId]: boolean }` — изученные темы теории |
| `ege2_variants` | массив `VariantResult` — история сданных вариантов |
| `ege2_flash` | состояние SRS-карточек `{ [term]: { box, due } }` (система Лейтнера) |
| `ege2_streak` | `{ count, last }` — серия дней подряд |
| `ege2_book` | лучший результат части 1 по каждому варианту сборника `{ [variant]: score }` |
| `ege_theme` | светлая/тёмная тема (не входит в облачную синхронизацию) |

> Префикс сменился с `ege_*` на `ege2_*` в v2.6 — это осознанный общий сброс прогресса у всех пользователей. Если понадобится сбросить прогресс ещё раз тем же способом — смените префикс снова в `storage.ts` и во всех местах, где ключи упоминаются напрямую (`grep -rn "ege2_"` по `client/src`).

Аналитика (Dashboard, WeakSpots) — агрегации `ege2_answers` на лету. Кнопка «Сбросить прогресс» на дашборде удаляет `ege2_answers`.

`PROGRESS_KEYS` (`storage.ts`) — ключи, которые синхронизируются в облако при входе (см. §11.2). Функция `write()` после каждой записи шлёт событие `ege:progress-changed`, на которое подписан слой синхронизации.

## 8. Деплой

CI описан в `.github/workflows/deploy.yml`:
1. триггер — пуш в `main` (или ручной запуск `workflow_dispatch`);
2. `npm ci` + `npm run build` в папке `client`, с секретами `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` и переменной `VITE_AI_ENDPOINT` (URL Cloudflare Worker, см. §11.1);
3. публикация `client/dist` на GitHub Pages.

GitHub Pages включён в режиме **GitHub Actions** (Settings → Pages → Source: GitHub Actions). Сайт обновляется автоматически за ~1–2 минуты после пуша (плюс до ~10 минут CDN-кэша GitHub Pages на статические ассеты).

Известная особенность: изредка сам шаг `actions/deploy-pages@v4` падает с «Deployment failed, try again later» без связи с содержимым коммита — в таком случае просто перезапустите упавший ран (`gh run rerun <id> --failed`) или сделайте пустой `workflow_dispatch`.

## 9. Как сделать типовые доработки (рецепты)

**Добавить задание** → допиши объект в `client/src/data/tasks.json` (см. §4.1), убедись, что `topic` из списка §4.5 и `id` уникален (больше текущего максимума). Пересобери (`npm run build`) или просто запусти dev.

**Добавить раздел теории/тему** → допиши в `theory.json`, дай теме уникальный `id`. Термины из `key_terms` желательно завести в `terms.json` в экзаменационном формате (см. §4.3).

**Добавить новый тип задания** → 1) расширь union `TaskType` в `types.ts`; 2) добавь ветку рендера в `TaskCard.tsx`; 3) добавь логику сверки в `checkAnswer()` в `lib/data.ts`.

**Поменять дневную цель / правила streak** → `DAILY_GOAL` в `Dashboard.tsx`; логика серии в `storage.ts`.

**Поменять длительность варианта** → константа `DURATION` в `Variant.tsx`.

**Сменить палитру/анимации** → цвета в `tailwind.config.js` (`theme.extend.colors`), кастомные keyframes там же (`theme.extend.animation`/`keyframes`) и в `index.css` (доп. классы вроде `.card`, `.lift-on-hover`, стили заставки).

**Поменять слоника/заставку** → SVG-разметка в `ElephantLogo.tsx` (лого) и `SplashScreen.tsx` (анимация мотания хоботом + «лопание»), тайминги — константы в начале `SplashScreen.tsx`.

**Переименовать репозиторий** → обнови `base` в `vite.config.ts` и все ссылки на URL Pages.

**Сбросить прогресс у всех пользователей разом** → смени префикс ключей в `storage.ts` (см. §5).

## 10. Известные ограничения и идеи для развития

- **ИИ-проверка ориентировочна** — даёт оценку по критериям, но не заменяет реального эксперта ФИПИ.
- **Нет тестов** (ни юнит, ни e2e).
- Данные заданий вшиваются в бандл (текущий JS-чанк ~3.5 МБ до gzip) — при дальнейшем росте контента стоит вынести данные в подгружаемые по сети файлы или включить код-сплиттинг (`vite build` уже предупреждает об этом).
- Подтверждение email при регистрации зависит от настроек Firebase Auth (Authentication → Settings → включить/выключить проверку email при желании).
- У части заданий части 2 (взятых из вариантов сборника, где OCR критериев побит) нет эталонного ответа из книги — доступна только ИИ-проверка по стандартным требованиям ФИПИ, без сверки с оригинальными критериями.

## 11. Настройка бэкенда: ИИ-проверка + аккаунты и облако

Сайт полностью работает и **без** этого раздела (офлайн-режим, прогресс в `localStorage`, кнопка «Проверить с ИИ» неактивна). Ниже — два независимых блока: ИИ-проверка (через Cloudflare) и аккаунты/облако (через Firebase).

### 11.1. ИИ-проверка через Cloudflare Worker

Ключ OpenRouter лежит в секретах воркера и никогда не попадает в клиентский бандл.

**Через сайт Cloudflare (без установки CLI):**
1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → **Create Worker** → задайте имя, **Deploy**.
2. **Edit code** → вставьте содержимое [`cloudflare/check-essay-worker.js`](cloudflare/check-essay-worker.js) целиком → **Deploy**.
3. Вернитесь на страницу воркера → **Settings → Variables and Secrets** → **Add** → тип **Secret**, имя `OPENROUTER_API_KEY`, значение — ключ с [openrouter.ai/keys](https://openrouter.ai/settings/keys) → **Save** (добавляйте секрет **после** первого деплоя кода).
4. Скопируйте URL воркера (`https://<name>.<account>.workers.dev/`).
5. Пропишите его в `.github/workflows/deploy.yml` в переменную `VITE_AI_ENDPOINT` (значение публичное, секрет GitHub не нужен) и локально в `client/.env.local`:
   ```
   VITE_AI_ENDPOINT=https://<name>.<account>.workers.dev/
   ```
6. Пуш в `main` → сайт пересоберётся с рабочей ИИ-проверкой.

Контракт воркера: `POST { taskNumber, question, answer, criteria, modelAnswer }` → JSON `{ perCriterion, score, maxScore, overall }` (или `{ error }`). Логика — `client/src/lib/ai.ts`.

### 11.2. Аккаунты + облачная синхронизация (Firebase)

**Стек:** Firebase Auth (email + пароль) + Firestore для прогресса. Выбран вместо Supabase, потому что бесплатный тариф Supabase **автоматически ставит проект на паузу после ~недели без обращений** — это уже дважды роняло вход и синхронизацию на проде. Firebase Spark (бесплатный) простой не карает.

#### Шаг 1. Создать проект Firebase
1. [console.firebase.google.com](https://console.firebase.google.com) → **Add project** → следуйте мастеру (Google Analytics не нужен).
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable**.
3. **Build → Firestore Database → Create database** → любой регион, режим **production**.
4. **Project settings** (шестерёнка) → **General** → **Your apps** → **Add app → Web** → скопируйте `apiKey`, `authDomain`, `projectId` из выданного конфига.

#### Шаг 2. Применить правила доступа Firestore
Firestore Database → **Rules** → вставьте содержимое [`firestore.rules`](firestore.rules) → **Publish**. Каждый пользователь получает доступ только к своему документу прогресса.

#### Шаг 3. Прописать переменные окружения клиента
**Локально:** скопируйте `client/.env.example` → `client/.env.local` и подставьте значения из шага 1.

**Для GitHub Pages:** добавьте в **Settings → Secrets and variables → Actions → New repository secret**:
- `VITE_FIREBASE_API_KEY`
- `VITE_FIREBASE_AUTH_DOMAIN`
- `VITE_FIREBASE_PROJECT_ID`

Workflow уже пробрасывает их в сборку. После добавления секретов сделайте любой пуш в `main`.

### Как это устроено в коде
| Файл | Роль |
|------|------|
| `client/src/lib/firebase.ts` | инициализирует Firebase App/Auth/Firestore из env-переменных; `isFirebaseConfigured` гейтит облачную логику |
| `client/src/lib/auth.tsx` | `AuthProvider`/`useAuth`: сессия, вход/регистрация, запуск синхронизации |
| `client/src/lib/sync.ts` | merge локального и облачного прогресса (документ `user_progress/{uid}` в Firestore), debounce-выгрузка |
| `client/src/lib/ai.ts` | вызов `VITE_AI_ENDPOINT` (Cloudflare Worker) |
| `client/src/components/AuthWidget.tsx` | кнопка входа/профиль в сайдбаре + модалка |
| `cloudflare/check-essay-worker.js` | прокси к OpenRouter (ключ в секретах воркера) |
| `firestore.rules` | правила доступа: пользователь читает/пишет только свой документ прогресса |

Логика синхронизации: при входе локальный и облачный прогресс **сливаются** (ответы/варианты объединяются без дублей, `learned`/`flash`/`streak` — разумным слиянием), результат пишется и локально, и в облако; дальнейшие изменения уходят в облако с debounce.
